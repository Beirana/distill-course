# 学生跟课手册（二稿）

> 配套课程视频使用。视频中演示的命令无法直接复制，请按本手册顺序操作。每一步给出目的、命令、预期结果三部分。原理讲解见 README 与《学生实验指南》。
## 实验概述

本实验将 Qwen2.5-7B-Instruct（教师）的解题能力蒸馏进 Qwen2.5-0.5B-Instruct（学生）。流程为：教师解题并由程序按五条标准筛选示范；学生先参加训练前基线测试；随后用 LoRA 方法学习教师示范；将训练产物合并为完整模型；最后在同一套题目上对比训练前后的表现。

## 第 0 步　开机检查（三件事）

**1. 重建数据盘目录。** 新实例的数据盘为空，工作目录中两个符号链接会悬空，跳过此步下载模型会报错：

```bash
mkdir -p /root/autodl-tmp/distill-assets/{models,cache}
```

**2. 环境体检。**

```bash
cd /root/distill-course && bash scripts/check_host.sh
```

预期：`PASS=16  WARN=1  FAIL=0`。那条 WARN 表示 huggingface.co 直连不可用，属预期现象，数据集下载走 hf-mirror 备援。

**3. 确认训练环境。**

```bash
/root/train-env/bin/python -c "import llamafactory, pathlib; print(pathlib.Path(llamafactory.__file__).parent)"
```

预期：输出以 `/root/distill-course/vendor/LLaMA-Factory` 开头。

**目录与数据速查。** 实验包 `/root/distill-course` 存放代码与材料；工作目录 `/root/distill-work` 存放实验产物；模型实体在数据盘，通过符号链接访问。数据的数量与来源集中在 `configs/course.json`（题池 1000、dev 100、test 300、种子 42），切分逻辑在脚本中，数据文件只是产出。修改 course.json 任意一个字符，已准备的数据即失效，须换新的数据根重新准备。

## 第 1 步　下载模型（约 27 分钟，可放后台）

```bash
export COURSE_DATA_ROOT=/root/distill-work
python scripts/course.py download-models
```

预期：结尾输出 `PAUSE P2`。中途断开可直接重跑同一命令，程序会续传补齐，不会重复下载。验证方法为再执行一次，应输出 `Reusing verified model: teacher` 与 `... student` 两行。

## 第 2 步　准备数据

```bash
export HF_ENDPOINT=https://hf-mirror.com
python scripts/course.py prepare-data
```

预期：镜像实例上输出 `Reusing verified prepared data`，属正常；全新机器才会现下载数据集。

三份数据的用途：

| 数据 | 数量 | 用途 |
|---|---|---|
| candidates | 1000 | 教师解题用的题池 |
| dev | 100 | 开发阶段评测，可反复使用 |
| test | 300 | 冻结后的最终测试，仅一次 |

**dev 回答"效果有没有"，考多少次都行；test 回答"最终是多少"，只考一次。** 不得依据 test 成绩调整参数。

## 第 3 步　smoke 流程验证（run 名自拟，建议含姓名，如 smoke-zhangsan）

| 序 | 命令 | 目的与预期 |
|---|---|---|
| 1 | `unset HF_ENDPOINT` | 关闭下载阶段设置的镜像入口 |
| 2 | `python scripts/run_stage.py generate --run <smoke> --mode smoke` | 教师生成 8 条示范，预期 `Accepted 8/8` |
| 3 | `python scripts/run_stage.py eval --run <smoke> --model before --split dev` | 训练前基线（dev 前 5 题） |
| 4 | `python scripts/course.py make-config --run <smoke>` | 生成训练与导出配置 |
| 5 | `export COURSE_TRAIN_ENV=/root/train-env` | 指定训练环境 |
| 6 | `python scripts/course.py train --run <smoke>` | LoRA 训练 2 步，秒级完成 |
| 7 | `python scripts/course.py export --run <smoke>` | 合并出完整模型 merged/ |
| 8 | `python scripts/run_stage.py eval --run <smoke> --model student --split dev` | 训练后对比 |

smoke 的正确率低属预期。2 步训练、8 条数据不足以提升能力，本步只验证流程完整。

## 第 4 步　正式实验（两条路线二选一）

**路线 A，自行生成 500 条（约 11 分钟）：**

```bash
python scripts/run_stage.py generate --run <正式run> --mode pilot500
```

预期：`Accepted 500/500`。生成完成后须人工抽读至少 10 条审计记录（`generation_audit.jsonl`）。

**路线 B，使用课程包附带的成品（节省 11 分钟，报告中须注明）：**

```bash
python scripts/use_materials.py prepared
python scripts/use_materials.py teacher500 --run instruct500-reference-01
```

注意顺序不能颠倒。此后正式 run 名为 `instruct500-reference-01`。

**两路汇合后的训练链：**

| 序 | 命令 | 目的与预期 |
|---|---|---|
| 1 | `python scripts/course.py make-config --run <正式run>` | 生成正式配置 |
| 2 | `python scripts/run_stage.py eval --run <正式run> --model before --split dev` | 完整基线，dev 100 题 |
| 3 | `python scripts/course.py train --run <正式run>` | 训练 96 步约 4 分钟（500 条 × 3 遍，等效批 16） |
| 4 | `python scripts/course.py export --run <正式run>` | 导出 merged 完整模型 |
| 5 | `python scripts/run_stage.py eval --run <正式run> --model student --split dev` | 训练后评测 |
| 6 | `python scripts/run_stage.py eval --run <正式run> --model teacher --split dev` | 教师上界参照 |

**查看结果：**

```bash
cd /root/distill-work/runs/<正式run>/eval_dev
python -m json.tool before_summary.json | head -15
python -m json.tool student_summary.json | head -15
python -m json.tool teacher_summary.json | head -15
```

解读：before→student 的差距是本次蒸馏的收益；student→teacher 的差距是剩余的提升空间。

## 第 5 步　终测与实验报告

```bash
python scripts/course.py freeze --run <正式run>
python scripts/run_stage.py eval --run <正式run> --model before --split test
python scripts/run_stage.py eval --run <正式run> --model student --split test
python scripts/run_stage.py eval --run <正式run> --model teacher --split test
python scripts/course.py report --run <正式run>
```

报告须包含三条披露：test 三百题在往届实验中使用过，不是全新基准；三百题不是完整评测基准；未依据测试成绩调整参数。报告另需：环境与模型版本、实际执行的命令、训练参数与耗时、前后指标对比、至少一例正确输出与一例错误输出、是否使用路线 B 的现成数据。

## 可选　双服务对比

```bash
# 终端A：训练前
vllm serve /root/distill-work/models/student --port 8001 --served-model-name base \
  --gpu-memory-utilization 0.25 --max-model-len 2048 --dtype bfloat16 --enforce-eager
# 终端B：训练后（<正式run> 换成自己的）
vllm serve /root/distill-work/runs/<正式run>/merged --port 8002 --served-model-name distilled \
  --gpu-memory-utilization 0.25 --max-model-len 2048 --dtype bfloat16 --enforce-eager
```

对话：`python chat.py 8001 base` 与 `python chat.py 8002 distilled`，同一题目各问一遍，输入 exit 退出。使用完毕在两个服务终端各按 Ctrl+C，运行 `watch -n 1 nvidia-smi` 确认显存归零后再执行其他任务。

## 常用命令与故障处理

```bash
watch -n 1 nvidia-smi                    # 显存实时监控（Ctrl+C 退出）
curl -s http://127.0.0.1:8001/v1/models  # 查询服务名（返回的 id 字段）
python scripts/verify_bundle.py          # 完整性自检，预期 Course bundle verified
```

| 现象 | 处理 |
|---|---|
| download-models 报 FileNotFoundError | 数据盘目录未建，回第 0 步第 1 条 |
| 粘贴长命令后停在 `>` 提示符 | 引号被复制源损坏，Ctrl+C 退出，改用脚本或分条粘贴 |
| 报 Run ID exists | 同名 run 已存在的保护，换新 run 名，不要删除旧目录 |
| 下载或准备中断 | 直接重跑同一条命令，程序自动续传或复用 |
